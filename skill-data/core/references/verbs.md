## Bundled Verbs

Verbs live under `cli/src/`, dispatched by `cli/src/main.rs` and grouped by lifecycle stage. Invoke them via `agent-qa <verb> [args]`. Do NOT rebuild them as ad-hoc bash.

### Recording

| Script                                                                                           | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start "<instruction>"`                                                                          | Picks a sortable SID, writes `tmp/scenario.env`, prints the dashboard URL, defaults to `--profile default-user`. Setup/teardown live under `env.open` / `env.close` in `scenario.json` — see [`prep.md`](./prep.md). |
| `smart-click "<accessible-name>" [--role <role>] [--ref @<eN>] [--no-record]`                    | Drift-proof click by accessible name. It snapshots at click time, rejects stale refs, scrolls into view, classifies submit/popup/navigation intent, and verifies the expected state change. **Auto-records** the gesture in-process (mirrors `fill-unique`) using the resolved role+name from the live snapshot — pass `--no-record` for legacy scripts that already pair smart-click with an explicit `record-step action`.          |
| `fill-unique <Label> --template <literal-with-{{vars._unique}}> [--save-as <name>]`              | Fill a uniqueness-constrained field and record a scenario/v1 template. Use `--save-as` whenever a downstream assert needs the replay-time minted value. The old binding flag is not supported.                                                                                                                                                                                                                                         |
| `record-step <navigation\|action\|wait\|assert> <triggerJson> [--session <name>\|--profile <p>]` | Records one step from the recording CLI shape. `flush` maps it into `scenarioSchema: 'scenario/v1'` with stable `stepId` and v1 discriminators (`goto`, `click`, `type`, `wait`, `assertUrl`, etc.). Writes `probes/`, `network/`, `snapshots/`, and `screenshots/` sidecars unless skipped by env.                                                                                                                        |
| `truncate <toStepIndex> [--archive-tag <slug>]`                                                  | Drop on-disk steps ≥ N from `tmp/scenario.steps.jsonl` and store their sidecars under `<sid>/failed/truncate-<isoTs>[-<tag>]/`. Does NOT drive the live tab — drive it yourself with `agent-browser` (`open`, `click`, `back`, `reload`, `fill <sel> ""`) before truncating. See [`recovery.md`](./recovery.md) for the scenario/2 recovery flow.                                                                                     |
| `flush`                                                                                          | Builds `<sid>/scenario.json` locally from buffered sidecars. The output root is `scenarioSchema: 'scenario/v1'`, `id`, `intent`, optional `setup` / `teardown`, and `steps[]`.                                                                                                                                                                                                                                                           |
| `verify [<scenarioId>] [--no-strict]`                                                             | Checks `scenario.json`, one keyframe per step, keyframe status, heal annotations, duplicate adjacent steps, and undeclared binding references. Resolves the SID from in-flight or last-flushed state when omitted.                                                                                                                                                                                                                     |

### Heal

| Script                                                                                                | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inspect [--last-n N] [--json]`                                                                       | Read-only state probe: URL, open dialogs, invalid fields, alerts/toasts, and recent GraphQL failures.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `detect-failure <stepIndex>`                                                                          | Reads the latest probe and exits 2 with structured failure JSON when alert/validation/lingering-modal signals are present.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `quarantine --reason <r> --diagnosis <d>`                                                             | Last-resort terminator. Writes failure evidence under `<sid>/failed/`, marks the scenario failed-self-heal, and clears in-flight sidecars.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `heal-promote <sid> [--run <runId>] [--steps <ids>] [--apply]`                                        | Promote replay-side suggested-diffs from `replays/<runId>/diffs/<stepId>.patch.json` back into `scenario.json`. Dry-run by default; `--apply` rewrites atomically. `scenarioContentHash` rebase guard refuses to apply against an edited contract (exit 3). Appends a `mode:"promoted"` audit row to `recording/heal.jsonl`. See [`heal.md`](./heal.md).                                                                                                                                                                                                                                                    |
| `heal-respond <sid> --step <id> [--run <runId>] (--value <X> [--rationale <text>] \| --reject)`       | Caller-driven heal response (Phase 5). Writes `replays/<runId>/heal-responses/<stepId>.json` with the corrected value (or refusal) + appends an audit row. Triggered by exit-7 from `replay` when `AGENT_QA_HEAL_LLM=1` and a value-rejection has no rule-based match. Re-invoke `replay --heal-from-run <runId>` to apply the override at step dispatch time. See [`heal.md`](./heal.md).                                                                                                                                                                                                                |
| `heal-apply <sid> --step <id> [--target-step <ref>] [--field auto\|seed\|pattern\|value] [--dry-run]` | Record-time `--update-snapshot` of a recording. After `heal-respond` writes a corrected value, patches the offending row's value template in `tmp/scenario.steps.jsonl` in place — preserves later rows + every sidecar byte-for-byte. Auto-resolves the target row by GraphQL variable byte-equality; `--target-step` overrides. Appends a `caller-driven-resolved` audit row, renames request file `.json` → `.applied.json` (idempotency marker), prints a re-execution checklist. NEVER touches the live tab. See [`heal-apply.md`](./heal-apply.md) and [`recovery.md`](./recovery.md). |

### Replay

| Script                                                                                                         | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `replay [<scenarioId>\|<path-to-scenario.json>] [--profile <p>] [--session <name>] [--param <name>=<value> ...]` | Active replay CLI. Replays a scenario document deterministically and writes the current replay sidecars/manifest under `<scenarioDir>/replays/<replayId>`. Single-profile only; use `compare --profiles ...` for multi-profile analysis. `--param` (alias `-p`) overrides a scenario-declared parameter (repeatable; last-write-wins on duplicates; sensitive values redacted in `replay.json` + stderr). See [`replay.md`](./replay.md) for the override contract. The internal v1 evidence helpers are stepId-keyed, but this CLI help does not promise that layout until replay is wired to it. |
| `compare [<sid>] [<replayId>] [--include json,snapshot,screenshot] [--pixel-threshold 0..1]`                   | Unified per-pair diff. 1:1 mode compares latest or pinned replay against the recording. Output lands under `<sid>/compare/<TS>__<labels>/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `diff ...`                                                                                                     | Permanent alias of `compare`; same flags, same output, same engine.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Compare

| Script                                                                            | Purpose                                                                                     |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `compare <sid> --profiles <p1,p2,...>\|all [--baseline <p>] [--force] [--serial]` | Cross-profile N-way mode. Profiles are run serially/reused when possible, then star-diffed. |
| `compare <sid> --replays <id1,id2,...> [--baseline <id>]`                         | Cross-replay N-way mode. Diffs existing replay folders only.                                |
| `compare <sid> --list-replays`                                                    | Lists replay ids with profile/status metadata and a copy-paste CSV for `--replays`.         |

### Profiles

| Script                                                                           | Purpose                                                                                   |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `doctor [--fix] [--quick] [--json]`                                              | Diagnose install, env, profiles, and auth setup.                          |
| `profile-add <id> --adapter <id> --email-var <N> --password-var <N> [--default]` | Register a new profile directory and optional default.                                    |
| `profile-bootstrap <profile>`                                                    | Idempotently sign in the profile via the registered auth plugin and apply session policy. |
| `profile-status <profile>`                                                       | Side-effect-free status probe.                                                            |

### Inspect

| Script                                                                                                    | Purpose                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `list [<scenarioId>]`                                                                                      | Prints step, keyframe, replay, and comparison summary; writes `<sid>/summary.md`.                                                                                                                                                                             |
| `perf-snapshot [--sid <sid>] [--profile <p>] [--record-renders <ms>] [--cpu-profile <ms>] [--trace <ms>]` | Optional performance sidecar under `<sid>/perf/`.                                                                                                                                                                                                             |
| `probe-step <stepIndex>`                                                                                  | Per-step DOM signals; auto-invoked by `record-step` and runnable standalone.                                                                                                                                                                                  |
| `parse-probe <probePath>`                                                                                 | Parse and pretty-print an existing probe sidecar.                                                                                                                                                                                                             |

If a script is missing or fails, fix the script. Do NOT inline its work in tool calls.
